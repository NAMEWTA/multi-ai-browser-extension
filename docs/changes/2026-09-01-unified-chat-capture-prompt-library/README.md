# 统一对话、回复采集与提示词库改造

> 状态：已实施并通过自动化验收
>
> 日期：2026-09-01
> 范围：统一对话、Markdown 保真、回复采集、页面扰动、提示词库

## 结论摘要

本次改造不能只做统一对话弹窗。当前回复在采集时已经被压成纯文本，只替换 React 展示组件无法恢复标题、列表、代码块和表格。推荐拆成四条彼此可验收的工作流：

1. 统一对话改为“轮次时间线 + 右侧问题导航”。打开时定位最后一轮，但所有 AI 回答仍默认收起，用户点击后才挂载和渲染正文。
2. 回复采集改为“通用观察内核 + 每站 adapter”。保存 `plainText + markdown`，旧记录继续按纯文本展示。
3. 移除无必要的聚焦和滚动。页面出现验证码、滑块、429 或风险提示时立即停止，不研究或实现反检测。
4. 在全局输入框旁增加提示词选择器和提示词库。选中的模板与本次问题只合成为一条消息，继续复用现有三阶段发送事务。

## 已确定的产品解释

- “默认是最后一轮的回答”解释为：打开统一对话后，最后一轮成为当前导航项并进入视口。
- “AI 回答都收起”没有例外：最后一轮里的各 AI 回答也保持收起。
- 右侧导航点代表用户问题，不代表 Provider；问题重复时仍用 `turn.id` 区分。
- 提示词是同一条用户消息中的前置模板，不是模型 API 的 system role，界面不得把它宣传为系统提示词。
- 没有选中模板时，发送内容仍是原始用户问题，不额外添加“用户”标签。
- 选中模板时，按提示词库顺序合成，不能按勾选先后产生不确定顺序。
- 发送成功后清空问题草稿，但保留提示词勾选，适合连续使用同一套模板。

## 推荐的千问边界

千问当前用户服务协议禁止未经授权的第三方插件自动操作和内容采集。推荐在未获得书面授权时，将千问网页保留为可手动使用的面板，但默认关闭自动发送与自动采集；需要稳定自动化集成时采用阿里云百炼官方 API，并由用户自行配置凭证。

这不是单纯的技术取舍。减少 `focus()` 引发的滚动属于正常兼容性修复；伪造可信事件、修改浏览器指纹、模拟鼠标轨迹或绕过验证码属于规避检测，不进入本项目方案。

## 实施决策

1. 采用“最后一轮默认定位，但全部 AI 回答仍收起”。
2. 千问保留现有网页发送能力并修复兼容性，但不实现反检测；实际启用前由使用者确认授权和服务条款。
3. 提示词库只做本机持久化，不进入会话 `.maiw.jsonl`；每轮采用的模板快照会随 Turn 导出。
