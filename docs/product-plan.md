# Multi AI Workspace 产品计划

> 状态：当前唯一产品执行基线  
> 版本：3.1
> 更新日期：2026-08-30

## 1. 产品定义

Multi AI Workspace 是 Chrome/Chromium 全页扩展工作台。用户只输入一次问题，扩展把同一段文字写入当前启用的多个真实 AI 官方网页，并触发各网页自己的发送按钮，方便用户直接并排查看和比较原生回答。

工作台不是新的 AI 客户端，不调用模型 API，也不重新绘制任何网站的聊天界面。每个面板展示真实网站，登录态、会员权益、会话、模型选择、文件能力和回答渲染均由该网站负责。

### 1.1 核心闭环

1. 点击扩展图标，打开或聚焦唯一的工作台标签页。
2. 从预配置站点中选择本次需要打开的 AI。
3. 工作台按用户选择的平铺或自适应模式展示已打开站点，不产生页面级横向滚动。
4. 用户在全局输入框中输入内容。
5. 输入内容实时同步到所有已启用且就绪的原生网页输入框。
6. 用户点击全局发送，扩展逐站触发原生发送动作。
7. 用户在原生网页内直接查看回答，也可以只在单个站点继续追问。
8. 本地历史只记录本次发送内容、时间、目标站点和发送结果。

### 1.2 明确不做

- 不自行渲染 AI 回答、聊天气泡或仿制网站首页。
- 不调用公开模型 API、私有接口或保存 API Key。
- 不读取、复制、修改或同步账号 Cookie。
- 不接管登录，不绕过验证码、付费墙、限流或网站风控。
- 不承诺从历史记录恢复当时的网页、URL、滚动位置或会话现场。
- 首版不做回答抓取、标注、笔记、Markdown/PDF/PNG 导出。
- 首版不把自定义 CSS selector 编辑器暴露为主流程。

## 2. 用户心智模型

用户看到的是一个“装有多个真实 AI 网页的浏览器工作台”，而不是“同时调用多个模型的聊天应用”。

| 用户操作         | 产品行为                                     |
| ---------------- | -------------------------------------------- |
| 打开扩展         | 打开或聚焦工作台标签页                       |
| 启用 3 个站点    | 只保留 3 个真实网页面板                      |
| 在全局框输入     | 将文字同步到 3 个网页的原生输入框            |
| 点击全局发送     | 分别点击 3 个网页的原生发送按钮              |
| 在一个网页内追问 | 只影响该网页，不广播                         |
| 点击历史记录     | 查看发送快照，不恢复旧网页                   |
| 网站未登录       | 面板显示网站自己的未登录状态，并提示用户处理 |

## 3. 首发范围

### 3.1 预配置站点

第一优先级：DeepSeek、Kimi、Coze。  
第二优先级：ChatGPT、Claude、通义千问、MiniMax。

用户已确认的正式网页入口：

| 站点     | 唯一正式入口                 |
| -------- | ---------------------------- |
| DeepSeek | `https://chat.deepseek.com/` |
| Kimi     | `https://www.kimi.com/`      |
| 通义千问 | `https://www.qianwen.com/`   |

Provider 默认地址和 host permission 必须以表中地址为准，不保留未确认的旧域名兼容入口。

每个站点必须独立通过以下门槛后才能标记为“可用”：

- 真实网页能在扩展工作台内加载，或被准确标记为仅支持普通标签页。
- 浏览器现有登录态可用。
- 能稳定定位可见、可编辑的输入框。
- 写入后网页 UI 能回读到完全一致的文本。
- 发送动作只在明确用户指令后发生一次。
- 网站改版或失败只影响自身面板。

Coze 官方文档当前明确说明其网页域名不支持第三方 iframe。因此 Coze 必须先作为高风险 Provider 做真实账号 POC；若无法稳定嵌入，产品应显示清晰的“在普通标签页打开”降级，而不是伪造一个 Coze 界面。

### 3.2 MVP 功能

- 唯一全页工作台。
- 预配置站点选择、打开、关闭、排序和刷新。
- 1 至 7 个内置站点面板支持平铺和自适应两种布局，均不得产生页面级横向滚动。
- 平铺模式从左到右展示，面板间边框可拖拽或用方向键调整，也可一键恢复等分。
- 自适应模式根据站点数和可用宽度自动排成 1 至 4 列，在当前页面内完整展示。
- 全局输入闲置同步、统一发送、发送确认和发送中防重复。
- 单站就绪、未登录、加载、发送、失败和降级状态。
- 面板最大化和恢复；操作不得重建其他 iframe。
- 普通标签页降级仍支持统一发送路由。
- 本地发送历史：提示词、时间、站点快照、逐站结果。
- 设置与历史均仅保存在本机。
- 可导出不含正文、Cookie 和回答内容的会话级诊断 JSON。

### 3.3 MVP 完成定义

- 在固定 Chrome Stable 环境中，DeepSeek 和 Kimi 的真实账号端到端统一发送成功率不低于 95%。
- 其他站点只有通过相同门槛后才展示“可发送”，未通过者必须明确降级。
- 一次任务拥有唯一 `taskId`，同一页面不得重复提交。
- 一个站点失败不会阻塞其他站点。
- 服务工作线程重启后可重新发现并绑定现有网页面板。
- 1440x900、1920x1080、2560x1440 和 1280x800 下无工具栏遮挡、按钮溢出或不可达区域。
- 单元测试、E2E、构建通过；真实站点 smoke test 结果逐站记录，不以 mock 结果代替。

## 5. 里程碑

| 阶段             | 交付物                         | 退出条件                  |
| ---------------- | ------------------------------ | ------------------------- |
| P0 基线收敛      | 最新文档与精简边界             | 不再引用历史方案          |
| P1 核心重构      | 新工作台、实时同步、轻量历史   | mock E2E 全通过           |
| P2 Provider 验收 | DeepSeek、Kimi、Coze POC       | 逐站形成可用/降级结论     |
| P3 扩展站点      | ChatGPT、Claude、千问、MiniMax | 逐站合同测试与 smoke 通过 |
| P4 发布准备      | 权限、隐私、商店材料           | 权限最小化与人工验收完成  |

## 6. 当前 Alpha 验收基线

- `0.0.1-alpha.3` 修复 DeepSeek 新版圆形发送控件定位，并区分回答生成中的停止控件，禁止误点。
- Provider 诊断由 Content Script 发送最小化消息，统一由 Service Worker 写入有界 `storage.session` 记录。
- 平铺布局支持相邻容器拖拽、键盘调整、双击或工具栏一键等分，宽度比例按面板保存。
- 自适应布局无需拖动底部滑轨；布局变化不得重建 iframe、抢走全局输入焦点或形成 ResizeObserver 反馈循环。

## 7. 风险与停止条件

- 删除 `X-Frame-Options` 或 `Content-Security-Policy` 只能作为受控 POC，不等于网站正式支持嵌入；若造成核心功能、登录、上传或支付异常，该站点转为标签页降级。
- Provider 适配不得依赖混淆 class 的单一 selector；改版后必须失败可见，不能误点页面其他按钮。
- 真实网页内容属于敏感用户数据。MVP 不抓取回答可显著降低数据访问面和商店披露复杂度。
- 若 Chrome Web Store 审核不接受相关 DNR 行为，公开商店版本必须使用标签页编排，嵌入版仅作为明确说明风险的本地开发形态。
