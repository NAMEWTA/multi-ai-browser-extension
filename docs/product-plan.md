# Multi AI Workspace 产品计划

> 状态：当前唯一产品基线
> 版本：6.0
> 更新日期：2026-08-31

## 1. 产品定义

Multi AI Workspace 是 Chrome/Chromium 全页扩展工作台。它在一个扩展标签页中并排打开多个真实 AI 官方网页，复用浏览器中已有的登录状态，让用户只提交一次问题即可比较各官网的原生回答。

扩展不是模型 API 聚合客户端，不重绘官网聊天界面，不接管账号和登录，也不复制 Cookie。网站的模型选择、会员权益、文件能力、上下文和回答渲染仍由网站自身负责。

## 2. 核心规则

1. 草稿只存在于工作台全局输入框。输入、修改、中文输入法组合期间均不得写入官网。
2. 点击发送后，系统冻结 `sessionId + turnId + prompt + targets`，先对全部目标做无副作用预检。
3. 任一目标预检失败，本轮不写入也不点击。全部预检通过后，先向所有目标暂存并回读内容；任一暂存失败则清空已暂存内容。全部暂存成功后才并发点击。
4. 官网点击发生后无法跨站回滚。提交阶段的单站失败必须作为部分失败记录，不能伪装成全局原子成功。
5. 没有点击“新任务”时，连续提问属于同一个 Session，各官网沿用原会话上下文。
6. 每个 Session 保存官网完整会话 URL、面板顺序、布局、选中目标和宽度。点击历史任务会原样恢复这些 URL，不解析或拼接官网路径。
7. 点击“新任务”时保留旧 Session 快照，并以相同站点组合和基础 URL 创建全新面板；首次发送后直接记录各官网生成的正式会话 URL。
8. 只有至少一个官网确认发送后才创建 Turn。全局预检或暂存失败不产生无效历史；每个有效 Turn 保存提问、逐站结果和可见回复纯文本。

## 3. 用户流程

```text
打开扩展
  -> 管理需要打开的官网
  -> 选择本轮发送目标
  -> 在全局输入框完成草稿
  -> 点击发送
  -> 全站只读预检
       -> 失败：零点击，保留草稿并显示原因
       -> 成功：全站暂存和回读
            -> 失败：清空全部暂存内容，零点击
            -> 成功：并发点击
  -> 并排查看原生回答
  -> 回复完成后写入当前 Session 时间线
```

用户可以在单个官网内手动继续操作，这不会广播到其他站点。下次统一发送前，如果官网输入框已有未发送内容或仍在生成，预检会中止整轮发送，避免覆盖用户操作或误点停止按钮。

## 4. 站点范围

预配置站点：DeepSeek、Kimi、Coze、ChatGPT、Claude、通义千问、MiniMax。

已确认正式入口：

| 站点     | 地址                         |
| -------- | ---------------------------- |
| DeepSeek | `https://chat.deepseek.com/` |
| Kimi     | `https://www.kimi.com/`      |
| 通义千问 | `https://www.qianwen.com/`   |

DeepSeek、Kimi 默认打开。其余站点由用户在站点管理器中打开。无法稳定嵌入的站点必须明确降级到普通标签页，不得渲染仿制页面。

## 5. 功能范围

### 5.1 工作台

- 唯一全页扩展标签页，重复点击扩展图标只聚焦现有工作台。
- 真实官网面板支持打开、关闭、排序、刷新、最大化和普通标签页降级。
- 平铺模式支持相邻边框拖拽、键盘微调、双击和工具栏一键等分。
- 自适应模式根据宽度排成 1 至 4 列，不产生页面级横向滚动。
- 站点打开状态与本轮发送选择相互独立；大量站点通过按需展开、可搜索的目标选择器管理。

### 5.2 发送事务

预检必须确认：

- 页面处于受支持 URL，Content Script 已连接。
- 登录和输入框状态可用。
- 官网输入框为空，不覆盖用户自己的草稿。
- 上一条回答未处于生成状态。
- 不检查发送控件；空输入时按钮可能尚未渲染或仍为 disabled。

暂存必须逐站完成：原生写入、文本回读一致、等待唯一可用发送控件。全部站点暂存成功后才提交并确认页面接受点击。同一 `turnId` 在同一页面只允许提交一次。

### 5.3 会话历史

```text
Session
  -> Turn 1
       -> DeepSeek Exchange: 提交状态 + 回复状态 + 回复正文
       -> Kimi Exchange
  -> Turn 2
  -> Turn N
```

- 左侧展示 Session，不再把每次发送拆成独立任务。
- Session 同时保存每个面板的完整 `location.href`、排列顺序、布局、发送选择和宽度比例。
- 点击 Session 主行会保存当前工作区并恢复目标 Session；独立的记录按钮打开问答时间线。
- 点击 Session 只切换，不改变列表位置；只有独立的置顶按钮可以改变置顶分组与顺序。
- 宽版统一对话弹窗按时间显示每轮提问及所有站点回复，并支持复制或下载 Markdown。
- 回复状态包括等待、生成中、完成、部分、超时、失败和暂不支持。
- 历史全部保存在本机 IndexedDB。

### 5.4 导入导出

- 文件扩展名：`.maiw.jsonl`。
- 第一行是格式、版本、导出时间和实体数量清单；当前格式固定为 v3，后续每行是一个 session、turn 或 exchange。
- 导入前完整执行结构、大小、Provider ID、数量和引用关系校验。
- 校验成功后通过单个 IndexedDB 事务写入；所有实体 ID 重映射，导入 Session 标记为 `imported`。
- 不导出 Cookie、账号凭证、诊断日志、网页 HTML 或附件。

### 5.5 Markdown 转录

- 顶部工具栏可以复制当前打开站点的最近一轮，或复制/下载当前任务完整会话。
- 每个 Provider 面板可以复制该 AI 的最后一次问答、完整会话，或下载独立 Markdown。
- 文档层级固定为 `# 会话标题 -> ## 用户问题 -> ### Provider`，保留完整提问和回复正文。
- 未采集完成、超时或失败必须在 Markdown 中明确写出状态，不以空白冒充答案。

## 6. 明确不做

- 不调用模型 API 或站点私有接口，不保存 API Key。
- 不绕过登录、验证码、付费墙、限流或网站风控。
- 不恢复滚动位置或原网页 DOM；只原样重开已记录的官方完整 URL。
- 不把历史回复重新注入官网。
- 不对用户开放任意脚本执行或任意 CSS selector 编辑器。
- 不进行无人值守批量发送。

## 7. 验收标准

- 编辑全局草稿 10 秒后，所有官网输入框仍保持原状态。
- 任一目标写入后仍缺少发送按钮时，所有目标的发送次数均不增加，已暂存输入全部清空，历史轮次不增加。
- 预检全通过时，每个目标恰好提交一次；刷新 Service Worker 不造成重复提交。
- 连续 A/B/C 三次发送只生成一个 Session 和三个 Turn。
- 点击“新任务”后旧 Session 的完整 URL 和布局保持不变，新 Session 以全新面板 ID 和基础 URL 打开。
- 在任务 A/B 间切换时，各面板按保存顺序恢复，地址逐字符等于官网此前上报的完整 URL（包含 query/hash）。
- 回复生成期间持续更新历史，稳定结束后保存最终可见纯文本。
- JSONL 导出后可在空数据库完整导入，ID 不冲突且内容、顺序和逐站状态一致。
- 点击历史 Session 不改变侧栏顺序；显式置顶和取消置顶后顺序按规则稳定恢复。
- 顶部、单站点和统一会话弹窗导出的 Markdown 层级、轮次及 Provider 顺序一致。
- 1280x800、1440x900、1920x1080 和 2560x1440 下无抖动、遮挡和页面级横向滚动。
- 单元测试、mock E2E、生产构建通过；真实站点 smoke 结果不能由 mock 代替。

## 8. 风险与停止条件

- 官网 DOM 随时可能改版。selector 必须优先语义属性，定位不确定时失败可见，绝不猜测点击。
- iframe 响应头调整只用于用户打开的精确站点和工作台 tab；若破坏登录、上传、支付或核心功能，立即转普通标签页。
- 回复“完成”是基于可见 DOM、生成控件消失和文本稳定窗口的推断。超时必须保存为部分回复，不能标记完整。
- Chrome 不允许 GitHub Release 静默安装未上架扩展；安装脚本只能完成下载、校验、解压和打开扩展管理页，最终加载需用户确认。
