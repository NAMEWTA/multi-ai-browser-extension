# Multi AI Workspace UI 与交互规范

> 状态：当前唯一设计基线
> 版本：4.0
> 更新日期：2026-08-30

## 1. 设计方向

整体采用安静、圆润、工作优先的浅色 AI 工作台。真实官网始终是视觉主体，扩展 UI 是克制的浏览器工具层：不做营销首页，不使用装饰性渐变、大面积品牌色、卡片套卡片或自动缩放的网页预览。

用户提供的 DeepSeek + Kimi 双栏截图是主要空间参考：官网占据绝大部分画面，全局输入框位于舞台上方，输入内容只在点击发送后进入官网。

竞品参考保留 ChatHub、Sider Group AI Chat、Multi、MultipleChat/Multii 与 Poe 中“任务附近选择模型、输入始终可达、比较列身份清晰、低频工具渐进呈现”的规律，但不采用其 API 聚合或自绘回答界面。

## 2. 页面结构

```text
┌──────────────┬──────────────────────────────────────────────┐
│ Session 侧栏 │ 顶部工具栏                                   │
│              ├──────────────────────────────────────────────┤
│ 新任务       │ 目标选择 · 全局草稿 · 统一发送               │
│ 搜索         ├──────────────────────────────────────────────┤
│ 会话列表     │ 真实官网 1 │ 真实官网 2 │ ...                │
│              │                                              │
│ 导入 / 导出  │                                              │
└──────────────┴──────────────────────────────────────────────┘
```

- 顶部工具栏高约 52px；侧栏默认 240px，可完全折叠。
- 主区统一使用 `minmax(0, 1fr)`，动态内容不得撑破轨道。
- 全局输入区宽度上限约 980px，始终位于官网舞台外，不遮挡官网控件。
- Provider 标题栏约 40px；其余空间完整交给 iframe。
- 页面不得出现底部横向滑轨。

## 3. 布局模式

### 3.1 平铺

- 所有面板从左到右一行排列，初始等分。
- 相邻面板之间为 8px 拖拽分隔条，只调整这两个面板的比例。
- 支持 Pointer Events、左右方向键、双击恢复等分和工具栏一键等分。
- 拖动期间 iframe 不接收 pointer event；结束后一次性持久化比例。

### 3.2 自适应

- 根据面板数量和舞台宽度选择 1 至 4 列。
- 窄视口通过增加纵向行完整展示，不横向滚动。
- `ResizeObserver` 只读取整数宽度，不改变 iframe 缩放，不形成反馈循环。

布局切换、拖拽、最大化和恢复均不得卸载其他 iframe、刷新官网或让全局输入框失焦。

## 4. 视觉令牌

```css
:root {
  --app-bg: #f5f7fa;
  --surface: #ffffff;
  --surface-muted: #f0f3f7;
  --text: #15171a;
  --text-muted: #667085;
  --border: #dfe3e8;
  --accent: #4f6ef7;
  --success: #16865c;
  --warning: #b26a00;
  --danger: #c63c3c;
}
```

- 字体使用系统无衬线，工作台内部标题保持紧凑，不使用 hero 字号。
- 字号不随视口宽度缩放，字距为 0。
- 控件圆角 8-10px；全局 composer 和主要浮层可使用功能性更大圆角。
- 品牌色只用于选中、发送和焦点，不形成单一蓝色页面。
- 图标优先使用 Lucide；陌生图标必须有 tooltip 与 `aria-label`。

## 5. 组件规范

### 5.1 Session 侧栏

- “新任务”是正式命令：在所有已打开官网中触发新对话并创建新 Session。执行中禁用重复点击并显示进度。
- 历史主行显示 Session 标题，次行显示当前/归档/导入状态和更新时间。
- 搜索匹配 Session 标题；删除会移除该 Session 的全部 Turn 和 Exchange，并二次确认。
- 底部提供独立的“导出”和“导入”按钮。导入选择器只接受 `.maiw.jsonl`/JSONL 文本，超过 50 MB 立即拒绝。
- 选中项使用中性底色和左侧 2px accent；删除仅在 hover/选中时出现。

### 5.2 Session 详情

- 右侧抽屉按从上到下的时间顺序显示 Turn。
- 每个 Turn 先显示用户提问，再按站点显示发送/回复状态和纯文本回答。
- `waiting`、`streaming`、`completed`、`partial`、`timeout`、`failed`、`unsupported` 必须有明确文案，不能只靠颜色。
- 回复使用可换行纯文本、`overflow-wrap:anywhere`，长内容不撑破抽屉。
- 导入会话是只读历史，不提供“恢复到官网”按钮。

### 5.3 顶部工具栏

- 左侧显示工作台名称和已打开官网数量。
- 中间为平铺/自适应 segmented control。
- 右侧为等分、诊断导出和“管理站点”。
- 工具按钮使用熟悉图标，不用带文字的圆角矩形代替明确符号。

### 5.4 Provider 面板

- 标题栏展示站点标识、名称、短状态、左右移动、刷新、最大化、普通标签页和关闭。
- 不再在每个面板标题重复发送复选框；发送目标只在全局输入框左侧管理。
- 状态提示不得覆盖大面积官网内容。
- 未登录显示官网原生登录页；扩展只在标题栏提示“需登录”。
- iframe 保持原生 CSS 像素尺寸，禁止整体 `transform: scale()`。

### 5.5 全局输入框

- 左侧是稳定尺寸的 `发送至 N/M` 摘要，最多叠放三个站点标记，避免 11 个站点挤压输入区。
- 展开后列出所有已打开官网，支持逐项勾选、全选、清空；超过 7 项出现搜索。
- 取消勾选只影响后续统一发送，不关闭官网、不丢失其当前会话。
- 草稿编辑绝不写入官网。占位文案必须明确“输入完成后点击发送”。
- 点击发送后显示单一 loading 状态；发送按钮在空草稿、零目标或事务执行中禁用。
- Enter 发送，Shift+Enter 换行，IME composition 不误发送。
- 预检失败时保留草稿，失败站点显示原因，其他站点显示“本轮已取消”而不是假装发送成功。

### 5.6 站点管理器

- 模态中以紧凑、可搜索列表展示站点名称、域名和实验性状态。
- 打开开关立即创建官网面板并默认加入发送目标；关闭立即移除面板、目标 ID 和布局比例。
- 站点管理只控制容器是否打开，不承担每轮目标选择。

## 6. 状态文案

| 面板状态      | 文案     | 含义                       |
| ------------- | -------- | -------------------------- |
| `loading`     | 载入中   | 等待官网和桥接连接         |
| `ready`       | 就绪     | 可参加下一次预检           |
| `submitting`  | 发送中   | 正在执行 Prepare/Commit    |
| `submitted`   | 已发送   | 已点击官网，等待或采集回复 |
| `needs-login` | 需登录   | 用户需在官网完成登录       |
| `blocked`     | 无法嵌入 | 使用普通标签页降级         |
| `error`       | 失败     | 查看原因、刷新或取消目标   |
| `unavailable` | 未连接   | frame/标签页桥接不可用     |

错误详情放在 title/详情区域。标题栏只展示可扫描短句，避免“似乎、可能、未知”一类不可行动文案。

## 7. 响应式与无障碍

- 最低目标视口 1280x720；更窄时允许侧栏折叠和自适应减少列数。
- 所有交互控件有键盘焦点和可见 2px focus ring。
- 图标按钮至少 32x32px，主要发送按钮至少 40x40px。
- 模态与抽屉使用正确 dialog 名称；关闭后焦点返回合理位置。
- 文本满足 WCAG AA；状态不只依赖颜色。
- 固定格式控件有稳定尺寸，loading、长站点名和状态变化不得引发布局抖动。

## 8. 验收清单

- 第一视口首先看到真实 AI 官网，而不是扩展自绘卡片。
- 全局输入 10 秒且反复修改时，官网 composer 内容与焦点均不变化。
- 2、7、11 个站点下目标摘要宽度稳定，完整目标只在展开时出现。
- 任一站预检失败时所有官网发送次数不增加，草稿仍在。
- 连续发送产生一个 Session 内从上到下的多个 Turn。
- 回复生成中可见更新，完成后历史显示逐站最终文本。
- “新任务”后官网上下文和本地 Session 同时切换，失败站点不会混入发送目标。
- 平铺拖动、自适应切换和最大化均无抖动、横向溢出、iframe 重载或焦点丢失。
