# Multi AI Workspace UI 与交互规范

> 状态：当前唯一设计基线  
> 版本：3.0  
> 调研日期：2026-08-30

## 1. 设计方向

整体采用“安静、圆润、工作优先”的浅色 AI 工作台，不做营销首页，不用装饰性渐变、悬浮大卡片或大面积品牌色。真实网页是视觉主体，扩展自身 UI 应像浏览器工具层一样克制。

用户提供的 DeepSeek + Kimi 双栏截图是首要布局参考：两个网页保持原生外观并占据绝大部分画面，全局输入框只负责跨站同步与发送。

## 2. 竞品调研结论

| 产品                  | 可借鉴模式                       | 不照搬内容                 |
| --------------------- | -------------------------------- | -------------------------- |
| ChatHub               | 单次输入、多模型并排、清晰比较列 | 自有模型/API 回答渲染      |
| Sider Group AI Chat   | 清晰的目标选择、一次提问多路回答 | 浏览器侧栏形态和功能堆叠   |
| Multi                 | Compare 模式、任务导向的模型选择 | 订阅/API 聚合与营销式页面  |
| MultipleChat / Multii | Duo、Trio、Quad 等直观布局心智   | 自有聊天卡片和统一账号体系 |
| Poe                   | 低学习成本的会话导航和模型入口   | 多 Bot 混合到一个会话线程  |

共同趋势是：模型选择靠近任务、输入区始终可达、比较列有明确身份、状态不遮挡内容、工具按使用频率渐进呈现。项目采用这些交互规律，但所有回答仍由真实网页原生渲染。

## 3. 页面布局

```text
┌──────────────┬─────────────────────────────────────────────┐
│ 历史侧栏     │ 顶部工具栏                                  │
│              ├─────────────────────────────────────────────┤
│ 新任务       │ 全局输入框 · 目标站点 · 发送                │
│ 搜索         ├─────────────────────────────────────────────┤
│ 发送记录     │ 真实 AI 网页面板 1  │ 真实 AI 网页面板 2   │
│              │                                             │
│              │                                             │
│ 设置         │                                             │
└──────────────┴─────────────────────────────────────────────┘
```

- 顶部工具栏高 52px，侧栏默认宽 240px，可折叠至 0。
- 主内容使用 `minmax(0, 1fr)`，不得被固定宽度面板撑破。
- 全局输入区位于顶部工具栏下方，宽度上限 980px；输入时不遮挡任何真实网页控件。
- 网页面板填满剩余区域；扩展工具条覆盖在面板顶缘，不增加厚重卡片层级。
- 1 个面板占满；2 个等分；3 个优先三列；4 至 7 个使用可滚动列或用户选择的网格。

## 4. 视觉令牌

```css
:root {
  --bg-app: #f5f7fa;
  --bg-surface: #ffffff;
  --bg-muted: #f0f3f7;
  --text-primary: #15171a;
  --text-secondary: #667085;
  --border: #dfe3e8;
  --accent: #4f6ef7;
  --success: #16865c;
  --warning: #b26a00;
  --danger: #c63c3c;
  --radius-control: 10px;
  --radius-panel: 8px;
  --radius-composer: 18px;
  --shadow-float: 0 10px 30px rgb(20 28 45 / 10%);
}
```

- 字体使用系统无衬线字体；正文 13px，辅助信息 12px，工作区标题 14px。
- 不随视口宽度缩放字号，不使用负字距。
- 品牌色只用于选中态、发送按钮和焦点环，页面不能读成单一蓝色主题。
- 圆润不是胶囊滥用：输入框与主要浮层可更圆，密集工具按钮使用 8-10px 圆角。
- 页面卡片最大圆角 8px；输入框和模态可使用更大的功能性圆角，不出现卡片嵌套卡片。

## 5. 组件规范

### 5.1 历史侧栏

- 顶部显示产品图标、新任务图标按钮和折叠按钮。
- 历史条目主行显示提示词摘要，次行显示站点数量和时间。
- 选中条目使用中性底色和左侧 2px accent，不使用高饱和整块背景。
- 点击只打开只读快照详情；详情明确显示“记录不会恢复原网页会话”。
- 删除等低频操作仅在 hover 或更多菜单中出现。

### 5.2 顶部工具栏

- 左侧显示当前工作台名称和已打开站点数量。
- 中间提供布局 segmented control。
- 右侧是“添加站点”主命令和历史栏开关。
- 使用 Lucide 图标；陌生图标必须有 tooltip 和 `aria-label`。

### 5.3 Provider 面板

- 面板标题只占 40px：启用复选框、站点图标、名称、状态、刷新、最大化、普通标签页、关闭。
- 状态使用图标 + 短文本；不使用覆盖网页的大面积提示。
- iframe 始终保留挂载。最大化时通过 CSS 隐藏其他面板，不卸载它们。
- 未登录显示原生网站登录页；扩展只在标题栏提示“需登录”。
- 加载失败显示紧凑错误层，提供刷新和普通标签页两项动作。

### 5.4 全局输入框

- 输入框是最重要的扩展控件，固定在网页舞台上方且不遮挡网页关键区域。
- 默认 48px，最多增长至 160px；textarea 内部滚动。
- 左侧显示当前目标站点的图标/首字母，可点击快速启停。
- 右侧使用圆形 Send 图标按钮；禁用、同步中、发送中状态清晰。
- Enter 发送，Shift+Enter 换行；IME 组合输入不会误发送。
- 输入时同步到网页但不触发发送。发送前若某站同步失败，该站不提交并显示独立错误。

### 5.5 站点选择器

- 使用模态对话框，不跳转到设置页。
- 内置站点以紧凑列表展示：图标、名称、嵌入能力状态和开关。
- 已打开站点不可重复添加。
- 实验性或仅标签页站点必须在用户启用前说明限制。

## 6. 响应式与无障碍

- 最低支持视口 1280x720；更窄时侧栏默认折叠，面板横向滚动，不把真实网页压缩到不可用宽度。
- 每个面板的渲染基准宽度不低于 720px；必要时使用内部等比缩放，缩放下限由真实站点 POC 确定。
- 所有交互控件提供键盘焦点和可见的 2px focus ring。
- 图标按钮至少 32x32px，主要发送按钮至少 40x40px。
- 文本对比度满足 WCAG AA；状态不只依赖颜色。
- 模态打开时锁定背景焦点，关闭后返回触发控件。

## 7. 状态文案

| 状态        | 文案                | 用户动作                   |
| ----------- | ------------------- | -------------------------- |
| loading     | 正在载入            | 等待或刷新                 |
| ready       | 可同步              | 正常输入                   |
| syncing     | 正在同步            | 等待，不阻塞其他站点       |
| needs-login | 需要登录            | 在当前网页或普通标签页登录 |
| submitted   | 已发送              | 查看原生网页回答           |
| blocked     | 无法嵌入            | 在普通标签页打开           |
| error       | 同步失败 / 发送失败 | 重试、刷新或降级           |

避免“可能、似乎、未知错误”等不可行动文案。错误详情放在 tooltip 或可展开区域，标题栏只保留短句。

## 8. 视觉验收清单

- 第一眼看到的是多个真实 AI 网页，而不是扩展自己的卡片。
- 全局输入框始终可达且不会遮住 Provider 页面发送按钮。
- 两栏场景与用户参考图的空间关系一致。
- 1、2、3、7 面板切换不出现布局跳动或工具栏挤压。
- 所有按钮圆润、尺寸稳定、图标一致，无文字溢出。
- 侧栏折叠、面板最大化和恢复不会刷新任何其他网页。
- 1440x900 与 1920x1080 截图中无空白 iframe、重叠、水平页面级溢出。
